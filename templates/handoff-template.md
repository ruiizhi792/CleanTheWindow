# CTW Handoff — seven fields

When asked to "write a handoff", produce a document with exactly these sections.
Be specific: file paths, commands, numbers. Do not editorialize.

## Goal
What the user asked for, in one or two sentences. Include acceptance criteria if stated.

## Current state
What exists right now: what is done, what is half-done, what compiles or runs.

## Next step
The single next concrete action, small enough to start without re-reading everything.

## Key decisions
Decisions made and why, one line each. Include rejected alternatives when relevant.

## Files touched
Every file created or modified, with a phrase about what is in it.

## Pitfalls / notes
Traps you fell into so the next window does not repeat them: broken commands,
flaky tests, wrong assumptions, environment quirks.

## How to verify
Commands to run and the expected outcome that proves the task state is intact.
